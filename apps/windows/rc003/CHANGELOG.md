# Changelog — Remote Mic RC003 (Windows)

从 `0.2.0` 起，程序、安装器、Python 包和发布资产统一使用同一个版本号。
正式版 tag 格式为 `v<版本>-windows`；测试候选使用 `<版本>-rc.<序号>`，
对应 tag 为 `v<版本>-windows-rc.<序号>`。早期 `0.1.0-hidtapfix.*` 条目作为
内部测试历史保留，不再用于后续正式发布。

## [0.2.0] — 2026-08-26 Windows 正式版

- 完成 RC003 Windows 桥接的真实硬件验收，包括配对、重启恢复、普通按键、
  返回键、音量键和麦克风语音链路。
- 通过随包并校验的 Frida Gadget 恢复部分 Windows 环境遗漏的返回键和音量键
  HID 报告，同时保留明确的 UAC、失败回退和诊断流程。
- 完成 ATVV 语音接收、虚拟音频桥接、系统麦克风统一输入、空闲释放和设置界面。
- 支持可配置的普通按键、快捷文本菜单、快捷键录制、登录自启动与检查修复入口。
- 麦克风键同时支持“直接长按”和“短按一次后再次长按”两种可配置手势，并为
  Typeless 提供防抖优化；普通快速双击不会误触发语音。
- Windows CI 从同一次构建生成安装器、便携版 ZIP 和 `SHA256SUMS.txt`，并检查
  Frida Gadget、版本号和发布资产完整性。

## [0.1.0-hidtapfix.33] — 内部测试：麦克风第二手势版

- 为 RC003 麦克风键新增可选的“短按一次后再次长按”手势；直接长按继续使用
  第一语音快捷键，第二手势使用独立的第二语音快捷键。
- 两个快捷键均可手动输入或通过录制按钮捕获；第二快捷键默认预填
  `ralt+space`，并可自由修改，不与具体软件绑定。
- 新手势默认关闭，避免升级后改变现有用户的即时触发时序；启用后以 250 ms
  长按确认和 450 ms 第二次按键窗口区分两种操作，普通快速双击不会误触录音。
- 语音会话记住本次手势选中的快捷键，结束、断线和清理时使用同一组合释放，
  防止右 Alt 或空格残留为按下状态。

## [0.1.0-hidtapfix.32] — 未发布 CI 完整包修复版

- Windows GitHub Actions 在 PyInstaller 构建前显式下载官方 Frida Gadget
  `17.15.3`，并按固定 SHA-256 校验；下载失败或哈希不符时构建直接失败。
- PyInstaller 完成后再次检查成品中的 Gadget 路径和 SHA-256，防止打包规则退化后
  仍上传缺少 HID tap 的便携版或安装版。
- `.31` 的应用功能不变；新版本号用于与此前未携带 Gadget 的 CI 产物明确区分。

## [0.1.0-hidtapfix.31] — 未发布语音快捷键录制版

- “连接”页的语音快捷键保留手动字符输入，并在右侧增加“录制”按钮。
- 录制对话框直接捕获实体键盘组合，区分左右修饰键；录制期间不会执行该快捷键，
  识别结果自动写回输入框，用户仍需保存并重启桥接后才正式生效。

## [0.1.0-hidtapfix.30] — 未发布虚拟音频桥接整理版

- “连接”页的音频卡片改名为“虚拟音频桥接”，下拉框标题改为“桥接到”；
  VB-CABLE 选中时直接说明 `CABLE Input` 与语音软件 `CABLE Output` 的对应关系。
- 默认列表只显示检测到的虚拟音频播放设备，同名的不同接口合并并优先选择
  Windows WASAPI；保留“显示全部设备”，兼容尚未识别的新虚拟声卡。
- 统一输入允许桥接到 VoiceMeeter 等其他虚拟声卡。只有 VB-CABLE 支持基于
  `CABLE Output` 的空闲检测；其他虚拟声卡自动关闭该选项并保持安全的持续转发，
  避免错误监听无关端点或意外静音。

## [0.1.0-hidtapfix.29] — 未发布语音触发说明版

- 日常触发方式精简并重排为“Typeless 专用（推荐）”“点按快捷键”“按住快捷键”；
  Typeless 只启动排障模式继续保留在底层以兼容旧配置，但不再出现在普通设置中。
- 触发方式只决定快捷键的点按/保持时序，不再自动覆盖用户输入或录制的语音快捷键；
  配置读写也停止根据快捷键猜测模式或把历史组合键隐式替换为右 Alt。
- 连接页明确提示 RC003 不支持点按后持续录音，所有模式都必须按住实体麦克风键
  才能持续传送声音；“点按/按住”仅描述电脑端快捷键行为。
- 按键映射页的麦克风行改为只读显示当前语音快捷键，并指向“连接”页设置，删除
  重复编辑与录制入口，避免两个页面产生冲突或误解。

## [0.1.0-hidtapfix.28] — 未发布连接页整理版

- “连接”页按真实操作顺序重组为“设备与运行状态、音频路由、遥控器语音控制、
  运行与启动”，合并原先分散的输出设备和统一虚拟输入卡片，并收紧卡片间距与
  内边距。
- 删除设备目录中的英文研发说明展示；桥接状态只陈述后台进程是否运行，不再让
  用户误解为遥控器已经连接。补充 `CABLE Input` 与语音软件 `CABLE Output` 的
  对应提示。
- 统一输入的系统麦克风和空闲释放选项改为缩进的从属设置，关闭主开关时整体灰显；
  语音设置按“触发方式、快捷键、说明”的顺序排列。
- 页面正文限制最大宽度并居中，保存/启动操作移到固定底栏，保存结果和错误不再
  漂在卡片之间；登录自启动与日志入口集中到“运行与启动”。

## [0.1.0-hidtapfix.27] — 未发布按需系统麦克风版

- “统一虚拟输入”新增默认开启的“空闲时释放系统麦克风”：通过 Windows Core
  Audio 检测 `CABLE Output` 是否存在活跃读取会话，只有真正使用虚拟麦克风时
  才打开并透明转发实体系统麦克风。
- 读取停止后保留 0.8 秒尾音保护再关闭采集流；RC003 仍原子切断系统麦克风并
  独占输出。RC003 结束后若没有虚拟麦克风消费者则直接回到“待机：系统麦克风
  已释放”，不制造空闲麦克风隐私图标。
- Core Audio 检测失败、端点热插拔或依赖不可用时回退到原持续转发行为并显示
  明确错误，优先保证现有语音功能；新增 pycaw/comtypes/psutil 仅作为随包 Python
  运行库，不安装新程序、虚拟驱动或服务。

## [0.1.0-hidtapfix.26] — 未发布快捷文本按钮修正版

- 按用户原意恢复快捷文本的按钮—弹窗编辑方式；按钮文字固定完整显示为“快捷文本
  菜单”，不再使用“编辑快捷文本…”或省略号。
- 为按钮保留其完整文字所需的最小宽度，并在应用最小窗口宽度的真实 QML 布局中
  验证按钮宽度不小于文字的隐式宽度，防止再次被压缩截断。

## [0.1.0-hidtapfix.25] — 未发布按键桥接恢复版

- 配置方案工具栏固定保持紧凑单行；移除多余的行内标签、收紧间距，并在应用最小
  窗口宽度下验证“＋ 新建方案”“重命名…”“删除”“保存当前方案”全部完整可见。
- 快捷文本编辑区不再折叠到“编辑快捷文本…”弹窗中，改为常驻展开在“检测真实
  按键”下方；标题、文本、启用、排序、删除和新增均可直接操作，项目较多时仅列表
  内部滚动。
- 设置页会持续检查后台桥接状态；桥接停止时直接提示长按、双击和普通按键均不会
  生效，并提供“启动桥接”按钮。新建、切换、保存或删除方案时也会自动启动缺失的
  桥接，使当前方案无需重开程序即可在下一次实体按键时生效。
- 增加桥接恢复和最小宽度真实 QML 交互测试，并继续覆盖长按抑制单击、双击只触发
  双击动作以及普通按键不受影响的回归场景。

## [0.1.0-hidtapfix.24] — 未发布统一虚拟输入版

- 新增默认关闭的“统一虚拟输入（遥控器优先）”：语音软件继续固定选择现有
  VB-CABLE 的 CABLE Output，Remote Mic 平时把用户明确选择的系统麦克风透明
  转发到 CABLE Input，不做降噪、变声或混音。
- RC003 语音开始时原子切换到遥控器并关闭系统麦克风采集；物理松键（带短防抖）、
  ATVV 语音结束、蓝牙断开、音频故障或清理退出时都恢复系统麦克风流程。唯一输出
  工作线程串行写入，禁止两路麦克风意外同时送入。
- 支持输入设备原生采样率和单双声道到虚拟端点的转换，切换时使用短淡出/淡入且
  保留首个音频块；系统麦克风热插拔、设备占用、输入中断和 VB-CABLE 写入失败会
  显示清晰状态并自动重试。
- “连接”页新增系统麦克风选择、当前音源/错误状态和隐私说明；功能关闭时运行时
  不构造系统麦克风采集流。继续保留 `.23` 的 Vibe Coding 动作、配置方案管理，
  并将“系统默认方案”固定为不可修改的只读模板。

## [0.1.0-hidtapfix.22] — 未发布现代编辑器光标定位版

## [0.1.0-hidtapfix.21] — 未发布长按防重复版

  低层键盘保护会持续吞掉同一遥控器按键的初始及重复 Enter，直到实际松键，避免

- 仅在遥控器的设备级按住区间内启用持续拦截，并设置丢失松键信号时的自动失效
  保护；遥控器未按住时，实体键盘 Enter 仍按原样通过。

## [0.1.0-candidate] — 2026-07-31

标签：`v0.1.0-windows-rc003-candidate.1`（基于 `6c33fcc`）

首个 Windows RC003 候选发布。本版本已在真实 RC003 遥控器上完成逐键、
语音链路验收（详见 README“真机验收”部分）。CI 与自动构建仍然不能
替代真机验证。

### 新增

- **Frida HID tap 旁路**：对 Windows 普通输入链路拿不到的返回、音量+、
  音量- 缺失 usages（`0xF1`、`0x80`、`0x81`），复用上游
  `remote-bridge-hub` 的 Frida Gadget WUDFHost tap 读取；扩展为上报
  遥控器全部键盘 usage，作为所有普通按键的输入旁路。Gadget 是可选的
  第三方二进制，需显式获取（`build/fetch-frida-gadget.ps1`）且验证
  固定 SHA-256 后才会启用。
- **豆包语音触发（DoubaoPhysicalizer）**：注入的右 Alt 合成事件此前被
  豆包输入法 `ImeService` 的低层键盘钩子以 `LLKHF_INJECTED` 标志忽略；
  现在附加到 `ImeService.exe` 的低层回调，只对该标记事件清除 injected /
  lower-integrity 标志并清空 `dwExtraInfo`，使豆包看到的按键形状与
  实体右 Alt 一致。默认按住模式 `ralt`、切换模式 `ralt+space`。
- **设置页独立入口**：`RemoteMicRC003Settings.exe` 与桥接 EXE 分离
  （后合并为单个 EXE，见下）。
- **按键采集/回放工具**：`src/rc003_key_test.py`、`rc003_key_probe.py`
  等诊断工具，被动记录真实物理签名，不执行映射动作。

### 修复

- **普通按键双触发**：方向键、OK 等按键按下时一次动作被触发两次。
  根因是低层键盘钩子阻塞了 `WM_INPUT` 派发，导致“先 arm 后吞键”的
  等待式方案永远慢半拍。改为由 Frida GATT tap 的独立 socket 线程在
  `NtDeviceIoControlFile` 报告到达时 arm，低层钩子零等待匹配并吞掉
  原生按键，只注入一次映射动作。方向/OK/Home/Menu/TV/Power/返回/
  音量键全部实测通过。
- **F5 语音键重复替换刷屏**：按住麦克风键期间键盘 auto-repeat 会让
  “替换为右 Alt”逻辑反复触发；为 transform 增加已按下/已发送守卫，
  只在真实按下/释放边沿各发送一次。
- **BLE GATT 特征找不到**：修复后反复出现
  `ATVV characteristic not found`；改用 `BluetoothCacheMode.UNCACHED`
  读取服务与特征，避免 Windows 缓存旧枚举结果。
- **设置保存失败且映射不生效**：配置文件改为临时文件 + fsync +
  `os.replace` 原子写入；Qt 设置保存捕获一切持久化/回读异常并在界面
  显示错误；桥接进程在按键前按 mtime 热加载新的按键映射，磁盘数据
  损坏时保留最后一份有效映射。
- **启动闪黑色命令行窗口**：桥接启动子进程与打包运行时的控制台子进程
  均使用 `CREATE_NO_WINDOW` 隐藏。
- **语音识别无声/不稳定**：语音输出改为按端点能力输出立体声并复制
  声道；解码后增加 20 Hz 一阶高通 DC 阻挡；默认增益提高到 +10 dB；
  16 kHz → 48 kHz 改有状态连续插值（对齐上游）。实机验收：豆包输入法
  能识别遥控器语音。

### 变更

- **单 EXE 行为**：合并为同一个 `RemoteMicRC003.exe`。双击（无参数）或
  `--settings` 打开设置窗口；`--bridge` 显式启动桥接进程。安装器/便携版
  的启动快捷方式统一使用 `--bridge`。
- **设置保存原子化**：`save_config` / `save_key_bindings` 走原子写入，
  不暴露半写的 JSON。
- **返回键默认映射**：保持 `delete_backward`（退格）语义；新增可选的
  “浏览器后退”动作供用户在设置页手动绑定。
- 普通按键仍通过 `SendInput` 注入映射动作；语音快捷键通过物理化的
  右 Alt 事件；两者互不混用。

### 已知限制

- 未签名，首次运行会触发 SmartScreen 提示，属预期行为。
- Frida Gadget 与 VB-CABLE 均为可选第三方组件；未显式获取/安装时，
  缺失 usages 不会被猜测伪造，语音默认没有虚拟麦克风路由。
- 遥控器没有独立物理静音键；“系统静音”只是可选手动绑定。
- 安装器与便携版运行期配置都写入 `%LOCALAPPDATA%\RemoteMic\RC003`，
  卸载不会自动删除。
